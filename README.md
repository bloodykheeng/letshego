# Letshego Field Sales: prototype and mockups

Demo-stage prototype of a field sales app for **Letshego Uganda**: an Android app for field agents and a web console for supervisors and management (brief of 29 September 2026).

- **Live prototype:** https://letshego-prototype.vercel.app (Vercel redeploys on every push to `main`)
- **Team briefing** (internal, not for Letshego): [`BRIEFING.md`](BRIEFING.md) · web version at `/briefing.html`
- **30 screens:** 14 web (1920×1080) and 16 screens of the Android agent app (360×800, to be built in Flutter)
- All names, figures, IDs and loan products are **illustrative**. District boundaries are real (UBOS).
- Brand colours were sampled from Letshego's LetsGo app: indigo `#2F2E80`, yellow `#FBD405`, the faceted triangle.

This README is for anyone, human or AI, who needs to change or extend the prototype. It follows the same method as the SNV prototype (`../../snv/mockups`).

---

## 1. How it was made

Nothing is drawn by hand. Every screen is **generated by Python** (`_src/`) as a plain **SVG** made of rectangles, paths, circles and live text. Browsers show it, and **Adobe XD imports it as editable layers**. The same Python records **hotspots** (clickable rectangles and the screen each one opens). `build.py` writes `prototype.html`, one self-contained page that shows one SVG at a time with invisible click areas on top.

```
_src/*.py  ──python build.py──►  web/*.svg + mobile/*.svg   (the screens)
                             └►  prototype.html              (viewer + all hotspots, embedded as JSON)
_src/combine.py ─────────────►  all-screens.svg             (every screen on one canvas, for one XD import)
_src/briefing.py ────────────►  briefing.html               (web version of BRIEFING.md)
```

## 3. The drawing kit (`_src/kit.py`)

**`SVG` class.** Each screen is `s = SVG(width, height, title)`. Drawing calls: `s.rect`, `s.circle`, `s.line`, `s.path`, `s.poly`, `s.text` (with `italic=True` for the wordmark), `s.para` (wrapped text) and `s.icon`. `with s.g("name"):` groups elements; ids become **XD layer names**.

**Text is measured, not guessed.** `tw(text, size, weight, italic)` measures with the real Segoe UI font files, so right-aligned and centred text lands correctly in importers that ignore `text-anchor`.

**Components:** `chip`, `status_chip`, `button`, `card`, `progress`, `avatar`, `checkbox`, `radio`, `toggle`, `field`, `table`, `triangle`, `logo_mark`, `wordmark`.

**Vocabularies** at the top of `kit.py`: `STAGES` (the client journey from the whiteboard, in order), `STATUS` colours, `PRODUCTS` (**placeholders** until Letshego confirms its catalogue). Change them there and every screen follows.

**Hotspots:** `s.link(x, y, w, h, "w05")` records a clickable area that opens screen `w05`.

## 4. Screens, keys and the build

**Every screen is a function** returning an `SVG`. The part of the name before the first underscore is its **key** (`w07_approvals` → `w07`, `m12_close` → `m12`). Hotspots and URLs use keys (`prototype.html#w07`).

| Web | | Agent app | |
|---|---|---|---|
| `w00` Sign in | `w07` Approvals queue | `m01` Splash | `m09` KYC 3: earnings & collateral |
| `w01` Sales overview | `w08` Application review | `m02` Sign in | `m10` KYC validation |
| `w02` Agents performance | `w09` Why & why not | `m03` Home | `m11` Negotiation |
| `w03` Agent profile | `w10` Journey plans & targets | `m04` Today's route | `m12` Close: submit application |
| `w04` Field map | `w11` Agent handover | `m05` Check in | `m13` Conversion recorded |
| `w05` Client pipeline | `w12` Users & territories | `m06` Not interested: why | `m14` My clients |
| `w06` Client record | `w13` Reports & audit | `m07` KYC 1: details · `m08` KYC 2: ID & photos | `m15` Client timeline · `m16` Me |

**Registration:** each module has a `SCREENS` list. Web screens are sorted by key; mobile screens run in list order. That order is what ← → steps through.

**Commands:**
```
cd _src
python build.py              # rebuild every screen + prototype.html
python build.py --png        # also render PNGs into _previews/ (headless Chrome)
python build.py w02 m07      # rebuild only matching screens (does NOT rewrite prototype.html)
python combine.py            # rewrite all-screens.svg
python briefing.py           # rewrite briefing.html from BRIEFING.md
```

**Renaming a screen changes its file name.** Delete the old SVG from `web/` or `mobile/`.

## 5. The clickable prototype (`PROTO` in `build.py`)

- Shows one screen scaled to the window; hotspots are placed in percentages so they stay aligned at any size.
- `#w05` in the URL opens that screen. No hash opens `w00` (or `m01` on phones).
- Click empty space to flash the hotspots; **H** keeps them visible; `?show` turns them on.
- **Keys:** ← → previous/next · **F** full screen · **Esc** exit.
- Splash `m01` moves to sign-in by itself after 1.8 s.
- Loads every SVG up front; the bar shows "✓ Offline-ready" when done.
- **≤ 760px (phones):** compact bar, app screens fill the screen with no phone frame, web screens fit the width with a "turn sideways" hint.

## 6. Adding or changing a screen

1. Write a function named `wNN_something` or `mNN_something`, starting from a similar screen. Web screens call `shell(...)` and use `X0`/`X1`/`CW`/`Y0`/`H`; phone screens call `phone(...)`.
2. Add it to that module's `SCREENS` list.
3. Add hotspots out of it and into it (menu entries go in `NAV_TARGET` in `web.py`).
4. `python build.py && python combine.py`, then check `prototype.html?show#<key>`.
5. Commit and push; Vercel redeploys.

**Rules that keep the story consistent:**
- **Conversion = application submitted with every required item.** Approval never changes it. Keep saying so on screens that show both.
- **Clients belong to Letshego, not to the agent.** Handover moves clients with their full history.
- The demo client is **Florence Nambi** (`CLIENT` in `data.py`): first visited by John Mugisha (left 12 Aug), moved to Sarah Namuli, KYC to application on 30 Sep 11:14–11:42, awaiting Moses Okello's approval.
- **Roles:** Field Sales Agent (Sarah Namuli) · Branch Supervisor (Moses Okello) · Regional Manager · HQ Credit Approver · Head of Sales (Patricia Nankya) · System Admin.
- The agent app is an **Android app built in Flutter** (not a PWA).
- Products, rates, the 50% affordability rule and the UGX 10M branch limit are **placeholders**.

## 7. Environment

- **Windows.** Fonts come from `C:/Windows/Fonts` (Segoe UI) in `kit.py`.
- **Python 3 + Pillow** (`pip install pillow`). Nothing else.
- **PNG previews** use headless Chrome at `C:\Program Files\Google\Chrome\Application\chrome.exe`. It won't render narrower than about 500px, so phone PNGs look cut off even when the real page is fine.
- **Vercel:** framework preset "Other", no build command, output directory = repo root. Generated files are committed; Vercel never runs Python.

---

## 8. Adobe XD

- **All at once:** File → Import → `all-screens.svg` → ungroup once. Each screen becomes a named group.
- **One at a time:** import any file from `web/` or `mobile/`.
- Edits made in XD are lost when a screen is regenerated; for lasting changes, edit the Python.
